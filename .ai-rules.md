# AI Development Rules for MedicalApp-Clean

## 1. Core Architecture Principles
- **Pattern:** Follow "Clean Architecture" (Domain, Data, Presentation layers).
- **State Management:** Use `Provider` (as established in previous modules).
- **Logic Separation:** Keep business logic in `Domain/UseCases`. No Firebase calls directly from the UI widgets.

## 2. Security & HIPAA Compliance (Strict)
- **Zero Leakage:** Never hardcode API keys, Strike secrets, or Firebase configs. Use `.env` or Firebase Remote Config.
- **Data Privacy:** All Patient Health Information (PHI) must be handled via secure `Models`. Ensure no PII (Personally Identifiable Information) is sent to external logs.
- **File Access:** When implementing sharing logic, always use **Firebase Signed URLs** with a maximum expiration of 10 minutes.
- **Authentication:** Every Firestore query must include a `.where('userId', '==', currentUid)` check to prevent cross-user data access.

## 3. Feature-Specific Requirements

### Data & Records (File Upload/Sharing)
- **Uploads:** Use `firebase_storage`. Files must be stored in `/users/{uid}/records/{fileId}`.
- **QR Sharing:** QR codes must only contain the signed URL or a temporary token, never raw database IDs.
- **Metadata:** When uploading a medical record (MRI/PDF), always include a `timestamp`, `category` (e.g., 'Lab Result'), and `isEncrypted` flag.

### Medication Logic
- **Notifications:** Use `flutter_local_notifications` for reminders.
- **Offline First:** Medication lists should be cached locally using `Hive` or `Sqflite` so patients can view them without internet.

### Payments (Visa & Strike)
- **Traditional:** Use the `stripe_sdk`. Always use "Test Mode" keys for development.
- **Crypto:** Use the `Strike API`. Ensure all Lightning Network invoices are verified via a webhook or Cloud Function before updating the UI.

## 4. Coding Style
- **Naming:** Use PascalCase for Classes, camelCase for variables/functions.
- **Documentation:** Every new Function or Widget must have a 1-line doc comment.
- **Testing:** For every new UseCase, create a corresponding test file in the `test/` folder.

## 5. File Locations
- **UI:** `lib/features/{feature_name}/presentation/`
- **Logic:** `lib/features/{feature_name}/domain/`
- **Data/Firebase:** `lib/features/{feature_name}/data/`
- **Functions:** `functions/src/`
## Data and Records Functions
* **FCM Token Registration**: Use a JS-First capture strategy. Flutter must poll `window.capturedToken` and send it to the backend via `POST /register-token`.
* **File Uploads**: Implement via `NetworkService` using `MultipartFile`. All uploads must be associated with a `patient_id`.
* **Security**: 
    * All backend requests must include a Firebase ID Token in the `Authorization: Bearer <token>` header.
    * Backend must verify the ID Token using `firebase-admin` before updating the PostgreSQL `fcm_tokens` table.
* **Medication Logic**: Records must follow the `MedicationModel` schema: `name`, `dosage`, `frequency`, and `last_taken_timestamp`.
